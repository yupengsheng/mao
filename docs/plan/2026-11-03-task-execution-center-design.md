# 执行记录界面技术方案

## 范围

在第一期 Task 执行记录之上提供可直接使用的桌面 / Web 共用界面。新增 `/execution-records` 路由及顶栏入口，展示当前用户的任务记录，按阶段和首次来源筛选、分页、选择详情，查看每次尝试的状态、实际来源、开始/结束时间、失败原因，并打开关联会话。

复用已有 JWT 查询接口与 UI 主题，不新增数据库迁移、调度策略或 LLM 调用。BLOCKED/QUEUED 保持契约中的预留语义；不增加审批等待识别、跨渠道归并或自主执行。本期把已有记录提供给用户检查，为下一步任务语义调整提供依据。

## 数据契约

`@mao/contracts` 导出 AgentTaskVO、TaskExecutionVO、TaskTriggerVO、TaskPageVO、TaskDetailVO 和 TaskListQuery。后端在 TaskService 将数据库实体转换成公开 VO，避免前端重复声明类型和依赖 deleted、policy_version 等存储字段。Stage/Source 汉化表用 Record 保证编译期穷尽。

Task.source 为首次来源；执行来源通过 Trigger.sourceEventId 与 Execution.executionId 关联。详情保留最近 50 次尝试和入口记录；只有终态回调的尝试开始时间显示“未记录”。

## 客户端状态与交互

独立 `useTaskRecords` 管理列表、筛选、分页和详情。过滤条件变化重置第一页及选中详情，翻页清空详情。列表和详情请求各自使用递增代次；切换后旧请求的成功/失败均不覆盖当前视图，卸载时使所有在途响应失效。失败显示错误和重试操作，不显示上一次成功加载的另一条记录。

首次挂载加载列表。手动刷新同时刷新列表和选中详情。每 10 秒仅在 document 可见且没有在途加载时刷新，离开页面后清理定时器。页面恢复可见时立即刷新；数据只存于组件作用域，不缓存到 localStorage。

详情按实际执行逐条展示结果及失败原因；未知值兼容显示原值，空记录有明确提示。打开会话复用已有会话路由；边路/子代理归属经本人会话接口读取后定位到根会话对应页签，不改变执行。关联会话不可访问时显示错误。

## 验证

先编写失败测试覆盖筛选翻页、列表/详情响应竞态、失败与重试、卸载后响应、每次实际来源；再实现契约、API 客户端、状态管理和页面。执行后端任务测试、桌面单元测试及官方 `npm run build`。使用本地模拟 API 检查页面交互，不接触线上数据。同步 CHANGELOG、README 和 mao-cli 产品手册。
